# Контекст для ИИ-ассистентов: ATLAS Campus

## Цель

Реализовать и поддерживать демонстрационный цифровой деканат для конкурсного прототипа. Вымышленные пользователи, никакой интеграции с вузом, публичный статус «концепт» на всех сценариях. Сайт от 360 px, обязателен контур безопасности и сохранения заявок.

## Инварианты, которые нельзя ломать

1. Ни один запрос студента не возвращает данные другого студента. `student_id` присваивает сервер из сессии, а не браузер.
2. У студента нет доступа к `/api/staff/*`; сотрудник не имеет доступа к студенческим API оценок и расписания.
3. Тестовые учётные данные — только вымышленные; никакой секретный ключ/пароль реального сервиса не коммитится.
4. Сохранение и повторная загрузка заявок работают; статусы меняет только сотрудник по допустимым переходам.
5. Публичное предупреждение «конкурсный прототип / все данные вымышленные» сохраняется.
6. На ширине 360 px горизонтальная прокрутка отсутствует во всех разделах.
7. Доступные состояния загрузки, пустого ответа и ошибки предусмотрены.
8. Все пользовательские строки в HTML проходят через `escapeHTML` или безопасный DOM API.

## Роли для следующей итерации (отдельные агентные поручения)

Эти роли **не являются фиксацией фактически использованных независимых агентов**: это инструкции для воспроизводимого продолжения работы.

**Product researcher**: выявляет 3–5 наиболее частых проблем студентов; проводит только реальные интервью после согласия участников; не придумывает ответы; связывает потребности со сценариями. Выход: `docs/research.md` с доказательствами, без ПДн.

**UX/Visual**: редактирует `static/index.html`, `static/style.css`, `static/app.js`, сравнивает вид на ширинах 360/390/768/1440 px; проверяет клавиатуру и доступность; не копирует логотип университета. Выход: скриншоты до/после с датами и списком отличий.

**Backend**: реализует контракты API и SQL-запросы, делает миграции при изменении схемы, добавляет тесты; не доверяет `student_id` в теле запроса. Выход: тест и запись контрактов.

**Security reviewer**: специально пытается раскрыть чужие `/api/requests/{id}`, `notifications`, `grades`, обойти роль сотрудника, CSRF, неправомерно изменить заявку. Выход: отчёт только с воспроизводимыми находками; никогда не вводит реальные логины.

**QA/Release**: проходит тестовые сценарии двумя студентами и сотрудником, проверяет отсутствие горизонтальной прокрутки, тесты, сохранение после перезапуска, доступность из РФ и TLS. Выход: `docs/release-checklist.md`.

## Обязательная последовательность после изменения

1. Найти задействованные API/контракты и угрозы.
2. Внести узкий набор изменений.
3. Проверить `node --check static/app.js`, `pytest -q tests/`.
4. Для UI проверить 360/390/1440 px; для backend — добавить негативные тесты IDOR.
5. Обновить README, скриншоты и фактическое описание ИИ-процесса. Не выдавать статические рендеры за реальные браузерные E2E-тесты публичного сайта.
6. Не заявлять «доступно из России», пока публичный адрес реально не проверен с российского подключения.


## Версия 3.2: текущие контракты

Схема 0005 аддитивная; не удалять БД. Студент добавляет уточнение или просьбу об отзыве, статус меняет только сотрудник. При переходе к записи сохранять id/date/subject/kind и проверки эпохи сеанса. Черновики принадлежат пользователю: ключ сохраняется до основной отправки, fingerprint - SHA-256, после await повторно проверяются uid и epoch. Новые проверки: tests/test_improvements_*.py и scripts/improvement_*.py. Реальные интервью, физические устройства и РФ не подменяются симуляцией.
