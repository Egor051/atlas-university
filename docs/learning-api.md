# Учебный контур АТЛАС 3.2.1 · 10 ноября 2026

Дополнение к общим контрактам API. Все маршруты ниже начинаются с `/api/learning`, требуют подтверждённой сессии **студента** и выбирают владельца из неё. Сотруднику они возвращают 403. Чужая запись, в том числе при подстановке номера, возвращает 404. Все изменяющие запросы — POST, с общим `X-Requested-With: ATLAS` и проверкой источника. Лишние поля (`student_id`, `score`, `role` и др.) запрещены. Пароли, сессии и личные данные не передаются внешним сервисам.

Это конкурсный учебный концепт. Запись о сдаче работы, отметка модуля, тест самопроверки и журнал времени сохраняются в прототипе. Они не отправляют работу реальному преподавателю и не меняют оценки, посещаемость или статус учебного задания в личном плане.

Личные конспекты, карточки, задачи и фокус-сессии дополнительно возвращают `record_token` (32 hex). Новый клиент передаёт его в `X-ATLAS-Record` при изменении, повторении или удалении записи. Неверный формат — 422, замена записи — 409 `record_changed`. Для старого клиента отсутствие заголовка допустимо; SQL всё равно сравнивает ID, владельца и токен прочитанной строки, защищая от повторного использования SQLite ID между чтением и записью. Для черновика существующей записи применяется имя `kind:id:record_token`. Старые `kind:id` доступны в личном экспорте черновиков для явного восстановления без автоматической привязки.

Создание и другие повторяемые операции принимают необязательный `Idempotency-Key` по [общему контракту](api-contracts.md). Проверка лимита и INSERT сериализованы на владельце. Старые записи сверх лимита сохраняются и показываются; лимит отклоняет только новое создание с 409.

## Курсы и материалы

| Метод и путь | Результат |
|---|---|
| GET `/courses` | `{items,summary:{course_count,credits_total,modules_done,modules_total}}` |
| GET `/courses/{id}` | Личный курс с материалами и прогрессом |
| POST `/courses/{id}/modules/{module_id}` | `{is_done:boolean}` → обновлённый курс |

Курс: `{id,subject,teacher,credits,description,color,modules:[{id,title,content,is_done}],progress,modules_done,modules_total}`. `progress` — процент отмеченных модулей. `module_id` — числовой ID, а не позиция. Проверяется одновременно владелец курса и принадлежность модуля этому курсу. `is_done` принимает только JSON boolean. Кредиты демонстрационные: 6 для экзаменационной дисциплины и 3 для зачётной; это не официальный учебный план вуза.

Демонстрационные материалы написаны для десяти вымышленных дисциплин: 4 коротких модуля на дисциплину. Нет выдачи внешней ссылки за загруженный учебник или копирования чужих материалов.

## Сдача учебных работ

| Метод и путь | Результат |
|---|---|
| GET `/assignments` | `{items,summary:{total,submitted,pending}}` — до 200 своих заданий из существующего `Deadline` |
| GET `/assignments/{deadline_id}` | Задание, инструкция и сохранённая сдача |
| POST `/assignments/{deadline_id}/submit` | `{text,url?}` → задание с обновлённой сдачей |
| POST `/assignments/{deadline_id}/withdraw` | Отзыв отправленной работы → задание с `submission.status:'withdrawn'` |

Задание: `{id,subject,title,due_date,is_done,instructions,overdue,submission}`. `submission` — `null` либо `{id,text,url,status,version,submitted_at,updated_at}`. Текст после trim — от 10 до 8 000 символов; URL — необязательная HTTPS-ссылка до 500 символов, без встроенного логина/пароля, обратной косой черты и пробельных символов. Сервер не загружает переданный адрес. Хранится только текст и строка ссылки; загрузки файлов в этом контракте нет.

Уникальное ограничение `(student_id,deadline_id)` предотвращает дубли. Повторная сдача обновляет сохранённую работу, время и версию; отзыв сохраняет текст для доработки. Повторный отзыв — 409. Конкурентные изменения проверяют прежнюю версию; конфликт — 409. `is_done` учебного дедлайна при сдаче и отзыве не меняется.

## Сессия и посещаемость

| Метод и путь | Результат |
|---|---|
| GET `/exams` | `{items,summary:{total,dated,risk_count}}` |
| GET `/attendance` | `{items,summary:{present,absent,excused,total,attendance_percent,description}}` |

Экзамен: `{id,subject,teacher,kind,exam_date,current,max_grade,assessment,risk,consultation,note}`. Риск — демонстрационный ориентир `current < 65`, неопределённый балл не превращается в ноль. Дата может быть `null` для зачётной дисциплины. Памятка направляет к отдельной записи на консультации.

Посещаемость: `{id,subject,day,status:'present'|'absent'|'excused',note}`. Данные фиктивные, только для чтения. Процент = present/(present+absent), уважительные пропуски исключены из знаменателя; при отсутствии знаменателя значение `null`.

## Личные конспекты

| Метод и путь | Результат |
|---|---|
| GET `/notes?q=...` | `{items}`; поиск до 100 символов по своим заголовку, дисциплине и тексту, без учёта регистра |
| GET `/notes/{id}` | Свой конспект |
| POST `/notes` | `{title,subject?,body}` → 201 |
| POST `/notes/{id}` | Тот же полный объект → обновлённый конспект |
| POST `/notes/{id}/delete` | `{ok:true}` |

Конспект: `{id,title,subject,body,created_at,updated_at}`. Заголовок — 1–180, дисциплина — до 130, текст — 1–12 000 символов, пустые после trim заголовок/текст запрещены. Это обычный текст; HTML не исполняется клиентом. Общий лимит HTTP-тела 32 KiB остаётся в силе, в том числе для многобайтового текста. До 200 записей на студента, упорядочены по времени изменения и ID.

## Карточки с повторением

| Метод и путь | Результат |
|---|---|
| GET `/flashcards` | `{items,summary:{total,due}}` |
| GET `/flashcards/{id}` | Своя карточка |
| POST `/flashcards` | `{subject?,front,back}` → 201 |
| POST `/flashcards/{id}/review` | `{known:boolean}` → обновлённая карточка |
| POST `/flashcards/{id}/delete` | `{ok:true}` |

Карточка: `{id,subject,front,back,due_date,reviews,known_count,interval_days,is_due}`. Вопрос — 1–500, ответ — 1–3 000, дисциплина — до 130 символов. До 200 карточек на студента. `known:true` увеличивает интервал 1 → 2 → 4 → … до 60 дней; `known:false` возвращает карточку в очередь сегодня, обнуляя интервал. Счётчик попыток защищает параллельное повторение от потерянного обновления; конфликт — 409. Это простой учебный алгоритм, а не заявление о применении SM-2 или другой специализированной модели.

## Самопроверка и история результатов

| Метод и путь | Результат |
|---|---|
| GET `/quizzes` | `{items}` — только личные тесты |
| GET `/quizzes/{id}` | Сводка теста и `questions:[{prompt,options}]`, **без ключа ответов и объяснений** |
| POST `/quizzes/{id}/attempt` | `{answers:[integer,...]}` → 201 с проверкой и объяснениями |
| GET `/quiz-attempts` | `{items,summary:{total}}`, все сохранённые попытки |
| GET `/quiz-attempts/{id}` | Своя попытка с объяснениями |

Сводка теста: `{id,title,subject,description,question_count,attempts,best_score,best_percent}`. До первой попытки `best_score` и `best_percent` — `null`. `best_score` — количество правильных ответов, `best_percent` — процент.

Попытка: `{id,quiz_id,title,subject,score,total,percent,created_at}`. При отправке и в деталях дополнительно `results:[{question,selected,correct,explanation,selected_text,correct_text}]`. Индексы вариантов начинаются с 0. Принимаются только целые числа JSON, не `true`, не строки. Число ответов должно точно совпасть с числом вопросов, каждый индекс — существующий вариант. Балл вычисляет сервер, прислать свой `score` нельзя. До 1 000 попыток на студента. Результаты не влияют на таблицу `Grade`.

В демо по два теста на студента: алгоритмы/вероятности у Алины, инженерия ПО/анализ данных у Марка. В каждом по три вопроса с разбором; это учебная самопроверка, а не экзаменационная система.

## Личные задачи

| Метод и путь | Результат |
|---|---|
| GET `/tasks` | `{items,summary:{total,done,overdue}}` |
| GET `/tasks/{id}` | Своя задача |
| POST `/tasks` | `{title,subject?,due_date,priority?,is_done?}` → 201 |
| POST `/tasks/{id}` | Тот же полный объект → обновлённая задача |
| POST `/tasks/{id}/toggle` | `{is_done:boolean}` → задача; изменяет только отметку, сохраняя остальные поля |
| POST `/tasks/{id}/delete` | `{ok:true}` |

Задача: `{id,record_token,title,subject,due_date,priority,is_done,created_at}`. Название — 1–180, дисциплина — до 130 символов. Приоритет `low|normal|high`, по умолчанию `normal`; `is_done` — строго boolean, по умолчанию false. Для новой или изменённой даты допустим период от 366 дней назад до 730 дней вперёд относительно учебного дня МСК. Неизменённую дату сохранённой задачи можно оставить за этим окном: возраст задачи не блокирует редактирование или toggle. До 200 задач. Личные задачи находятся в отдельной таблице и не изменяют выданные преподавателем дедлайны. Checkbox использует отдельный toggle и не отправляет устаревшую копию названия, приоритета или даты.

## Журнал самостоятельной работы

| Метод и путь | Результат |
|---|---|
| GET `/focus-sessions` | `{items,summary:{total,minutes,today_minutes,week_minutes,description}}` |
| POST `/focus-sessions` | `{subject,minutes}` → 201 |
| POST `/focus-sessions/{id}/delete` | `{ok:true}` |

Запись: `{id,record_token,subject,minutes,created_at}`. Тема — 1–130 символов, минуты — строго целое число от 1 до 180. До 1 000 новых записей, все сохранённые доступны списком; сводка считается по всем записям. `today_minutes` использует границы дня `Europe/Moscow`, переведённые в UTC для совместимости SQLite и PostgreSQL. `week_minutes` — тот же подход для текущей недели понедельник–воскресенье; UI сравнивает его с собственной целью `services/preferences.weekly_goal`. Запись можно удалить из журнала через подтверждение. Это введённое студентом время, а не подтверждённая системой длительность присутствия.

## Хранение, миграция и проверки

Модели добавляются к SQLAlchemy metadata в `app/learning_db.py`, таблицы создаются аддитивно: существующие пользователи, заявки и учебные данные сохраняются. `seed_learning(db)` запускается под общим startup lock и дополняет только два известных вымышленных аккаунта, однократно на студента по маркеру `LearningSeed`. Повторный запуск не сбрасывает прогресс и не восстанавливает удалённые личные записи.

Проверено 26 тестами `tests/test_learning.py`: роли и анонимный доступ, отрицательные проверки чужих ID для всех изменяемых семейств, CSRF, подмена владельца и балла, некорректные URL/типы, повторная сдача и отзыв, хранение после повторной инициализации, неизменность оценок и учебных дедлайнов, граница московского дня. Локальная команда: `.venv/Scripts/python.exe -m pytest -q tests/test_learning.py`. Эти API-тесты не являются браузерной проверкой публичного сайта.

Регрессии 3.2.1 находятся в `tests/test_audit_backend_integrity.py`: реальная SQLite-замена ID между owned SELECT и каждым изменяющим действием пяти личных семейств, конкурентное достижение лимита, сохранение существующих записей сверх лимита, частичный toggle, старые даты, 12000-символьный черновик, сохранение данных при двукратной миграции и безопасный повтор старой квитанции карточки. Фактические результаты общего запуска фиксируются в [приёмочном листе](release-checklist.md).
