# Эксплуатация конкурсного стенда

Публичный стенд: [atlas-university.ru](https://atlas-university.ru/). Состояние и доказательства — в [приёмке 11 ноября](production-acceptance-2026-11-11.md). На VPS используйте рабочий каталог и переменные Compose из [инструкции развёртывания](deployment.md#управляемое-развёртывание-на-подготовленном-vps).

```sh
sudo systemctl list-timers 'atlas-*'
sudo journalctl -u atlas-campus.service -u atlas-monitor.service -u atlas-backup.service --since '1 hour ago' --no-pager
sudo systemctl start atlas-backup.service
```

Для контрольного восстановления под root из `/opt/atlas-campus` экспортируйте `/etc/atlas-campus/compose.env` и запустите `python3 scripts/production_restore_verify.py --report /var/lib/atlas-ops/restore-verification.json`. Скрипт создаёт новую БД и сравнивает число строк и хеши всех таблиц. Если посетители изменили данные во время сравнения, отчёт не объявит совпадение; выберите короткое тихое окно. Рабочая БД не перезаписывается.

Отдельная копия выгружается на компьютер владельца; локальная задача «ATLAS Campus - protected backup» запускается в 09:00 и при первой возможности после пропуска, пока пользователь вошёл в Windows. Она не требует новых ключей. Конфигурация защищена отдельно средствами Windows, привязанными к текущему пользователю. Для восстановления на другом компьютере сохраните также доступ к хранилищу секретов. Следите за сроком оплаты, внешним мониторингом и получением уведомлений.

## Ежедневная проверка

Проверьте `docker compose ps`, `curl --fail https://ВАШ-ДОМЕН/api/ready`, свободный диск (`df -h`) и `docker compose logs --since 24h --tail 100`. Секретные значения из `.env` не копируйте в сообщения или отчёты. Логи приложения не должны содержать пароли, токены сессии или текст заявок. Внешний мониторинг должен проверять HTTPS readiness с площадки вне VPS; наблюдение из РФ подтверждается отдельно.

Сохраняйте стенд и домен рабочими до 28 ноября 2026 включительно. Настройте оплату и уведомления хостинга так, чтобы сервер и DNS не отключились до окончания конкурса. Эти действия выполняются в аккаунте владельца инфраструктуры.

## Резервная копия PostgreSQL

Из корня проекта на Linux:

```sh
sh scripts/backup.sh
```

Скрипт выполняет `pg_dump` в custom-формате, проверяет чтение оглавления через `pg_restore --list`, сохраняет SHA-256. Файл создаётся с закрытыми правами, сначала как `.partial`; при ошибке незавершённый файл удаляется. По умолчанию каталог `backups/`; можно задать `ATLAS_BACKUP_DIR=/srv/backups/atlas`. Не храните единственную копию на том же VPS. Выгружайте копию и checksum в отдельное защищённое хранилище. Сохраняйте `.env` в менеджере секретов отдельно от дампов.

Для проверки целостности из корня проекта выполните `sha256sum -c backups/ИМЯ.dump.sha256`. Контрольная сумма обнаруживает повреждение копии; защита от подмены требует отдельного доверенного хранения checksum и ограничения доступа.

Проверка оглавления выявляет повреждённый формат, но не заменяет восстановление. Раз в неделю и перед обновлением выполните пробное восстановление:

```sh
sh scripts/restore.sh backups/atlas-ДАТА.dump atlas_restore_20261106
```

Скрипт разрешает только новое имя `atlas_restore_...`, отклоняет небезопасные имена, не удаляет и не очищает действующую БД. `createdb` завершится ошибкой, если цель существует. Восстановление выполняется одной транзакцией с остановкой при первой ошибке; затем выводится количество заявок. Сравните число пользователей, заявок и событий, пройдите вход и историю документа на изолированной копии. Переключение рабочей строки подключения делается отдельно в запланированное окно после проверки.

Для тестового Compose задайте `COMPOSE_PROJECT_NAME` и `COMPOSE_FILE` точно так же, как при его запуске: иначе команды обратятся к обычному стеку `atlas-campus`.

## Обновление и откат

Образы Python, PostgreSQL и Caddy закреплены immutable digest, чтобы сборка была воспроизводимой. Перед обновлением сверяйте исправления безопасности с [релизами Python](https://www.python.org/downloads/release/python-31318/), [PostgreSQL](https://www.postgresql.org/docs/17/release-17-11.html) и [Caddy](https://github.com/caddyserver/caddy/releases/tag/v2.11.9). На 6 ноября 2026 выбраны Python 3.13.18, PostgreSQL 17.11 и Caddy 2.11.9; digest нужно обновлять явно после проверки, иначе `docker compose pull` сохранит прежний закреплённый образ. Закрепление версии не заменяет будущие обновления и проверку уязвимостей.

1. Сохраните текущие исходники/тег образа, `.env` и проверенный дамп.
2. На отдельной копии прогоните API, browser-проверку и восстановление дампа с миграциями новой версии.
3. Обновите исходники, выполните `docker compose build web`, затем `docker compose up -d --wait --wait-timeout 180`.
4. Проверьте readiness и вход. Зафиксируйте версию исходников и дату развёртывания в release-checklist.

При неуспехе не удаляйте том PostgreSQL. Верните предыдущий образ, если он совместим с текущей схемой; при несовместимой схеме восстановите заранее проверенный дамп в новую БД и планово переключите приложение. Автоматического разрушительного downgrade нет. Миграции приложения добавляют версии схемы; старую БД не нужно удалять для запуска новой версии.

## Локальная SQLite

`atlas.db` принадлежит локальному приложению, содержит только вымышленные записи и не входит в исходный ZIP. Для резервной копии остановите сервер и скопируйте файл в защищённый каталог; при работающем сервере используйте SQLite backup API, чтобы не получить несогласованную копию WAL. Дальнейший переход на PostgreSQL — запуск production-конфигурации и, при необходимости, отдельный проверенный перенос данных; простое переименование SQLite-файла не является миграцией данных в PostgreSQL.

## Граница готовности

Подготовлены переносимый код, версионирование схемы, production-конфигурация и сценарии эксплуатации. До работы с настоящими студентами необходимы реальный провайдер идентификации, отдельная модель выдачи учётных записей, политика обработки и хранения данных, юридические основания и независимая проверка безопасности. Конкурсный стенд остаётся публичной демонстрацией с вымышленными аккаунтами; не вводите в него настоящие персональные данные.
