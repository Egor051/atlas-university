# Независимая проверка расширения ATLAS Campus

Дата: 7 ноября 2026 года. Проверялись локальные исходники учебного контура, сервисов кампуса, портфолио, общего поиска, управления сессиями и клиентского расширения `static/campus.js`. Все аккаунты и данные вымышлены. Проверку проводил отдельный ИИ-агент роли Security reviewer / QA; он не писал реализацию проверяемых API и не менял клиентскую реализацию.

## Фактически выполнено

`tests/test_campus_security.py`: **8 проверок успешно**. Объединённый запуск с `tests/test_learning.py` и `tests/test_services.py` на момент проверки: **44 проверки успешно**, два предупреждения об устаревающих интерфейсах тестовых библиотек. База SQLite — отдельная временная; рабочий `atlas.db` не открывался и не изменялся.

```powershell
.venv/Scripts/python.exe -m pytest -q tests/test_campus_security.py tests/test_learning.py tests/test_services.py
```

Независимая проверка включает:

1. Обход всех зарегистрированных API расширений `/api/learning/`, `/api/services/`, `/api/campus/`, `/api/account/`: запрос без сессии возвращает 401; персональные ответы имеют `Cache-Control: no-store`.
2. Каждый изменяющий запрос расширения без подтверждающего заголовка и с чужим Origin возвращает 403. Все API сотрудника закрыты студенту; сотрудник не читает студенческие учебные данные, финансовую ленту и портфолио.
3. Чужое портфолио нельзя изменить или удалить, а результаты поиска и HTML-экспорт не содержат записей другого студента. Подмена `student_id` в query не переключает владельца; лишнее поле в JSON отвергается.
4. Строки `<script>` и `<img onerror=...>` в названии и описании экспортируются как текст; HTML-документ имеет CSP sandbox. Опасные схемы ссылок, учётные данные в URL и управляющие байты отвергаются.
5. Список сессий не содержит токенов или их хешей. Команда «завершить остальные сессии» отзывает второй сеанс своего пользователя, сохраняет текущий и не затрагивает другого студента.
6. Два разных студента одновременно занимают последнее место консультации и мероприятия либо последний экземпляр книги. Реальные параллельные SQL-запросы дают ровно один успех 201 и один конфликт 409.
7. Два браузерных сеанса владельца одновременно отменяют одну запись/регистрацию либо возвращают одну книгу. Ровно один ответ 200 и один 409; счётчик освобождается один раз. Чужая отмена возвращает 404. После освобождения второй студент успешно занимает место.
8. Два отдельных Python-процесса работают с одной временной БД. После многократного запуска миграции и демозаполнения сохраняются изменённый конспект, намеренное удаление исходных личных задач, отметка модуля, настройки, сданная работа, запись на консультацию и её счётчик, выдача книги и тема переписки. Исходные задачи не создаются заново.

Смежные тесты владельцев модулей дополнительно проверяют IDOR конспектов, карточек, заданий, попыток теста, личных задач, сообщений, записей и выдач; строгие типы; автоматический подсчёт результатов; отсутствие ключа правильных ответов в GET; уведомление после ответа сотрудника и невозможность писать в закрытую тему. Эти файлы были прочитаны и их тесты реально запущены указанной выше командой.

## Найденные и исправленные ошибки времени

**Граница учебного дня в журнале фокус-сессий.** SQLite отбрасывает timezone у `DateTime`, поэтому сравнение UTC-записей с московской полуночью без перевода в UTC теряло первые три часа московского дня. Реализация исправлена: граница дня переводится в UTC до SQL-запроса. Регрессия `test_focus_today_uses_moscow_midnight_in_sqlite_and_postgresql` с фиксированным днём включает запись в 22:00 UTC предыдущей даты и исключает 20:59 UTC; она прошла в локальном запуске SQLite. Название теста не является свидетельством отдельного запуска на PostgreSQL.

**Сохранение времени консультаций и мероприятий.** Входное `15:00+03:00` при прямой записи в SQLite превращалось в наивное `15:00`, которое клиент затем трактовал как UTC. До сохранения входные timestamps и демозаполнение теперь явно переводятся в UTC; часовой пояс обязателен. Изменение сделано владельцем сервисного модуля по результату независимого чтения кода. Проверки границ и времени в сервисной suite дополняются её автором.

По чтению кода также унифицирована проверка поисковой строки через общий `search_text`, чтобы управляющие символы не попадали в SQL-поиск сотрудника. Это профилактическая правка; сбой работающего PostgreSQL с таким запросом в этой проверке не воспроизводился и не заявляется как установленная уязвимость.

## Независимая браузерная проверка и исправленные гонки

`tests/test_extension_frontend_security.py`: **3 реальных браузерных сценария успешно** после исправлений. Chromium запускался с отдельным локальным HTTP-сервером и временной SQLite-базой. Ответы успешных API не подделывались: для воспроизведения гонок задерживались настоящие ответы сервера.

```powershell
$env:ATLAS_RUN_BROWSER_TESTS='1'
.venv/Scripts/python.exe -m pytest -q tests/test_extension_frontend_security.py
```

1. **P1 — результат теста прежнего аккаунта поверх нового.** Студент А отправлял тест; ответ 201 доходил, а последующий реальный GET обновления задерживался. Во время обновления можно было выйти и войти студентом Б. После получения старого GET функция продолжала выполнение и открывала результат А поверх кабинета Б: повторной проверки поколения сессии после `await updatePage()` не было. До исправления регрессия падала: находилась одна `.campus-quiz-results` вместо нуля. Основной исполнитель добавил проверку поколения сессии и текущего раздела после обновления; регрессия прошла.
2. **P2 — варианты ответов другого теста в разборе.** Загрузка первого теста задерживалась; пользователь закрывал её и открывал второй. Поздний ответ первого менял локальный объект теста, хотя соответствующий диалог уже не показывался. При сдаче второго теста вместо выбранного `P(A)+P(B)` разбор показывал `O(n²)` из первого. Теперь присвоение локального состояния проверяет актуальность диалога, ответы берутся из открытой формы, а подписи разбора — из серверного результата. Регрессия сначала воспроизвела ошибку, после правки прошла.
3. **Вставка пользовательской разметки.** Через реальные POST создавались конспект и проект со строками `<b>`, `<img onerror>`, закрытием `textarea` и `<svg onload>`. В карточках и редакторе они остались текстом; соответствующих внедрённых DOM-узлов нет. Внешняя ссылка проекта сохранила HTTPS и `noopener noreferrer`.

По чтению клиентского кода также найдены и переданы основному исполнителю несогласованные поля: свободная категория мероприятия вместо серверного enum; число правильных ответов вместо процента; неверный счётчик активных заявок; пределы полей карточки памяти; сумма журнала только по видимой странице; календарный день консультаций в UTC вместо МСК; переходы новых уведомлений. Исправления перечитаны и согласованы с текущими DTO. Эти замечания по отображению не объявляются отдельными обнаруженными уязвимостями.

## Границы результата

Это локальная проверка API на SQLite, три браузерные регрессии и чтение кода. Публичный хостинг, доступность из России, новый deployment на PostgreSQL, TLS, физический телефон и браузерная геометрия в эту независимую проверку не входили. Общая браузерная приёмка, доступность и итоговый результат всей suite отражаются основным исполнителем отдельно в документации выпуска.

При первом полном запуске всей suite обнаружено устаревшее ожидание списка revisions в `tests/test_workflows.py`: фактическая аддитивная миграция `0004_full_campus` добавилась к двум прежним. Основной исполнитель обновил ожидаемый список; это не потеря данных или отказ миграции. Окончательный полный запуск выполняется после завершения интеграции.
