# Приоритеты функций: основание и неопределённость

9 ноября 2026. Частота и значимость потребностей среди настоящих студентов **не измерены**. Приоритет ниже задан ТЗ и техническими зависимостями; это не результат опроса.

| Разделы | Задача / основание | Решение до исследования |
|---|---|---|
| Вход, профиль | Обязательное ядро ТЗ | Сохранить, обеспечить безопасность и разные данные |
| Главная, расписание, успеваемость | Обязательное ядро и повседневный учебный контекст | Выделить в постоянной навигации, исправить точные переходы |
| Заявки и справки, уведомления | Обязательное ядро, сохранение и результат | Завершить workflow и устойчивый повтор |
| Мой план, сдача работ | Поддержка действия по учебному сигналу | Явно разделить личную отметку, сдачу и оценку |
| Дисциплины, сессия, консультации, связь с офисом | Гипотеза полезного следующего шага | Связать с предметом и предусмотреть отсутствие слота |
| Календарь, личные задачи | Гипотеза единой повестки | Точные переходы; исследовать модель и названия |
| Посещаемость, конспекты, карточки, самопроверка, фокус | Дополнительная гипотеза учебного сопровождения | Сохранить во вторичных группах, не увеличивать ядро |
| Библиотека, события, финансы, контакты, помощь | Дополнительные сервисные гипотезы | Исправить поиск/страницы/даты; проверить спрос |
| Портфолио, настройки | Дополнительное личное пространство | Сохранить существующее, проверить повторную пользу |
| Учебный офис, пульт, диалоги сотрудника | Необходимый ответ на студенческие действия | Ограниченные права, история и понятный ответ |

Новых разделов ради количества не добавлено. После исследования для каждой функции нужны код наблюдения, частота только в своей выборке, тяжесть препятствия и решение сохранить/изменить/отложить. Связанные проблемы отражены в `research.md`, технические сценарии — в `api-contracts.md`, первичные данные будущего исследования — в `research-kit/`.
