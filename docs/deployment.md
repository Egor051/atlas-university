# Перенос ATLAS Campus на сервер

Дата: 6 ноября 2026. Приложение остаётся неофициальным конкурсным концептом с вымышленными данными. Публикация на домене и доступность из России — отдельная приёмка после установки. Этот документ не утверждает, что публичный сайт уже существует.

## Локально на Windows

В PowerShell из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Install
```

Повторный запуск: `powershell -ExecutionPolicy Bypass -File scripts/start.ps1`. Параметр `-NoBrowser` отключает автоматическое открытие браузера, `-Port 8001` меняет порт. Скрипт слушает только `127.0.0.1`, использует локальный `atlas.db`, не читает облачные учётные данные и не сбрасывает заявки. Остановка — Ctrl+C. Если порт занят, укажите другой. Переноситесь на сервер вместе с исходниками, но не переносите `.venv`.

## Что требуется от VPS

- Linux, Docker Engine с современным плагином Docker Compose, минимум 2 ГБ RAM, свободный диск и резервная копия вне сервера. Локально проверены Engine 29.9.2 и Compose 5.6.1.
- Домен с A-записью на IPv4 VPS; если задана AAAA, она также должна указывать на работающий IPv6 этого VPS.
- Входящие TCP 80/443. Доступ к SSH ограничен правилами сервера. Порты 8000 и 5432 наружу не открываются.
- Для конкурсного требования выбирайте площадку и подключение, которые сможете проверить из России без VPN до 28 ноября 2026.

## Запуск HTTPS-стенда

Загрузите исходники на сервер. Выполните из корня проекта:

```sh
cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(36))"
```

Откройте `.env`: замените `DOMAIN` на имя хоста без `https://` и пути; вставьте сгенерированный пароль в `POSTGRES_PASSWORD`. Повторите генерацию и задайте другой пароль в `ATLAS_APP_PASSWORD`. Используйте URL-safe пароли из команды, чтобы символы `@`, `:` и `/` не изменили строку подключения. Сохраните `.env` с правами `chmod 600 .env`. Не публикуйте этот файл.

```sh
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 180
docker compose ps
curl --fail https://ВАШ-ДОМЕН/api/ready
```

Caddy получает публичный сертификат ACME только при доступных 80/443 и правильном DNS. Приложение запускается в production-режиме: PostgreSQL, Secure/HttpOnly cookie, точный HTTPS origin, разрешённый hostname. Некорректная конфигурация блокирует запуск. Миграции версии схемы выполняются до обслуживания запросов и защищены блокировкой; существующие записи сохраняются.

`DEMO_MODE=true` оставляет публичные вымышленные аккаунты жюри. `DEMO_MODE=false` отключает заполнение демонстрационных данных и блокирует запуск, если в базе остались публичные demo-логины. Это пустая установка для дальнейшей интеграции; в текущем концепте нет регистрации реальных пользователей или SSO. Переключение флага не превращает конкурсный стенд в сервис для настоящих персональных данных.

## Проверка после переноса

```sh
python3 scripts/check-deployment.py --url https://ВАШ-ДОМЕН
```

Сценарий использует только три публичных вымышленных аккаунта: проверяет вход, изоляцию студентов, идемпотентную подачу, смену статусов сотрудником, результат документа, уведомления, календарь и сохраняемый дедлайн. Он создаёт одну тестовую заявку; её номер напечатан в JSON. После `docker compose restart web db` дождитесь готовности и повторите с `--request-id НОМЕР`, чтобы подтвердить сохранение.

Дополнительно откройте сайт на телефоне, проверьте все разделы, скачивание документа и календаря, выполните сценарий с двумя студентами и сотрудником. Проверьте URL с российского подключения без VPN, запишите дату и источник проверки в `docs/release-checklist.md`. Не заменяйте эту проверку локальным успешным тестом.

## Локальный тест PostgreSQL и HTTPS

`compose.test.yaml` предназначен только для проверки на компьютере, с отдельным project name, собственной БД и внутренним сертификатом Caddy:

Первый раз скопируйте `.env.example` в `.env.test`, замените `DOMAIN` на `localhost`, задайте два разных случайных пароля. Сохраните этот файл для повторных запусков тех же тестовых томов: изменение переменных не меняет пароли в уже созданной БД.

```sh
export COMPOSE_PROJECT_NAME=atlas-release-check
export COMPOSE_FILE=compose.yaml:compose.test.yaml
export COMPOSE_ENV_FILES=.env.test
docker compose up -d --build --wait --wait-timeout 180
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt /tmp/atlas-test-ca.crt
python3 scripts/check-deployment.py --url https://localhost:18443 --ca /tmp/atlas-test-ca.crt
docker compose down
```

В PowerShell для `COMPOSE_FILE` используется разделитель `;`. Публичный TLS и DNS этим тестом не проверяются. Тестовый корневой сертификат передаётся только конкретному процессу проверки; устанавливать его в системное хранилище не требуется. Не используйте `compose.test.yaml` на публичном сервере. `docker compose down` сохраняет тома; флаг `-v` в инструкциях намеренно не используется.

## Сети и ограничения контейнеров

Web работает от непривилегированного пользователя с файловой системой только для чтения, временным `/tmp`, удалёнными capabilities и лимитом одновременных соединений. PostgreSQL находится во внутренней Docker-сети без публичного порта. Приложение подключается ролью `atlas_app` без прав superuser, создания БД или ролей; `atlas_admin` используется для администрирования и резервного восстановления. Пароль администратора не передаётся web-контейнеру. Роль приложения создаётся `deploy/init-db.sh` только при первом запуске пустого тома PostgreSQL. Если вы переносите существующий том старой версии, сначала сделайте backup и создайте роль/выдайте права в отдельной административной миграции; не удаляйте том.

Caddy и web имеют отдельную proxy-сеть `172.30.60.0/24`; только адрес Caddy `172.30.60.10` считается доверенным источником proxy-заголовков. Адрес web назначается Docker автоматически. Если эта подсеть занята вашей инфраструктурой, измените subnet, адрес Caddy и `--forwarded-allow-ips` в Dockerfile и Compose согласованно, затем пересоберите образ. Не устанавливайте `*` для доверенных прокси.

В production Compose по умолчанию запускаются два web-процесса (`WEB_WORKERS=2`). Миграции и начальное заполнение сериализуются блокировкой PostgreSQL; ограничение входов хранится в общей БД. Количество процессов можно менять под ресурсы VPS: у каждого свой пул соединений и потребление памяти, поэтому увеличение требует нагрузочной проверки. Для нескольких узлов нужен общий PostgreSQL и настроенный балансировщик; этот Compose предназначен для одного VPS.

Готовность `/api/ready` проверяет соединение с БД, `/api/health` сообщает жизнеспособность HTTP-процесса. Эти URL не раскрывают учётные данные или записи студентов. PostgreSQL-том, сертификаты и конфигурация Caddy сохраняются между перезапусками.

## Исходный архив для передачи

```powershell
powershell -ExecutionPolicy Bypass -File scripts/package.ps1
```

В `dist/` появятся ZIP, SHA-256 и перечень файлов. В архив входят исходники, документация, тесты и снимки; исключаются локальная БД, `.env`, виртуальное окружение, кеши, резервные копии и история Git. `.env.example` включается как безопасный шаблон. Перед отправкой просмотрите manifest. В архиве нет настоящих пользовательских данных, но контроль содержания документации и снимков перед публичной отправкой остаётся необходимым.
