11 ноября 2026 года. Сборка ручной приёмки на Windows `87835a508cb284c1`.
Снимок Git с переводами строк LF формирует идентификатор `1b355fd318deac86`.
Код этих двух сборок совпадает после нормализации переводов строк.
АТЛАС Campus — конкурсный концепт с вымышленными
персонажами, учебными данными и документами. Приёмка использует локальные
серверы и отдельные базы. Браузерные снимки получены из работающего
приложения.

## Архитектура и границы доступа

- Фронтенд использует общую оболочку и модули каталога, учебных операций и подразделений. Они передают маршруты, параметры и карточки в одну навигацию. Браузер сверяет сеанс до применения ответов к экрану.
- Сервер определяет личного владельца из сеанса, проверяет роль и предметную область в каждой операции. Сотрудники расписания, деканат, администратор, профсоюз и ВУЦ имеют отдельные полномочия. Преподаватель видит ведомость и работы закреплённой группы.
- Схема 0007 добавляет каталог, материалы и директ. Схема 0008 добавляет назначение на группу, аудитории, расписание, задания, отзывы, квитанции и версии учебных отметок. Схема 0009 добавляет заявления, членство, программы и учёт ВУЦ.
- Подтверждение импорта повторно проверяет данные и пишет их одной транзакцией. Повтор возвращает сохранённую квитанцию. Публикация расписания, последний доступный слот и решения по заявлениям проверяются с учётом конкурентных операций.
- База ручной приёмки отделена от существующей рабочей SQLite. Штатный Windows-запуск принимает путь к выбранной локальной SQLite через `-DatabasePath`.

## Ошибки, устранённые на приёмке

| Воспроизведение | Исправление и повторная проверка |
|---|---|
| Преподаватель открывал карточку задания и получал 500 после изменения загрузки обратной связи | Карточка вызывает актуальную загрузку отзывов. API-тест открывает её до сдачи, после сдачи и после добавления комментария. Браузерный тест проходит публикацию, сдачу, просмотр, оценку и переход из уведомления. |
| Число вне поддерживаемого диапазона в таблице приводило к 500 при предварительном просмотре | Сравнение диапазона выполняется без округления огромного числа. Проверка получает ошибку с номером строки. Отдельные тесты отклоняют битый файл, неверную кодировку, внешнюю связь и чрезмерный размер распаковки. |
| Слишком большой номер заявления или истории ВУЦ и профсоюза приводил к 500 SQLite | Номера ограничены диапазоном схемы до обращения к БД. Тест проверяет ответы 422 для неверного ID и курсора и 404 для чужой записи. |
| Штатный запуск выбирал только рабочую `atlas.db` | Добавлен явный путь к отдельной SQLite, использованный для ручной приёмки. Путь по умолчанию для обычного локального запуска сохранён. |
| Замер производительности искал ссылку в свёрнутой группе старого меню | Сценарий раскрывает группу, когда нужная ссылка скрыта, и учитывает этот шаг во времени перехода. Пороги замера сохранены. |

## Локальный сервер

При передаче на ручную приёмку сервер был оставлен работающим
по адресу [http://127.0.0.1:8000](http://127.0.0.1:8000).
Запуск выполнен через `scripts/start.ps1` с отдельной базой
`tmp/manual-acceptance-2026-11-11/atlas.sqlite3`, схема 0009.
Проверены ответы сервера, вход и выход всех 11 аккаунтов и открытие
студенческого раздела в Chromium. На момент передачи база содержала
начальные демонстрационные записи. Хеш рабочей `atlas.db` совпал до и после
комплексной проверки. [Проверка запущенного сервера](verification/final-local-2026-11-11/manual-smoke.json).

Если сервер остановлен, его можно запустить снова из корня проекта
с той же базой и сохранённым состоянием.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Port 8000 -DatabasePath .\tmp\manual-acceptance-2026-11-11\atlas.sqlite3 -NoBrowser
```

## Границы приёмки и статус публикации

- Редактор меняет занятия управляемого расписания. Посещаемость хранится
  по дисциплине и дате. Публикации используют HTML с исходным текстом
  из редактора или файла TXT/MD.
- Импорт принимает UTF-8 CSV и XLSX из одного листа со значениями. Предел
  файла 22 КБ, строк 200, столбцов 32. Расписание из таблицы создаёт
  проекты для согласования.
- Членство, помощь, отбор и результаты демонстрационные. ВУЦ использует
  два вымышленных подтверждения в форме приёма. Реальные выплаты,
  документы и интеграции с вузом требуют отдельного проекта.
- Ширины экрана эмулировались. Физические телефоны, ручная проверка
  скринридером и публичная сеть относятся к отдельной приёмке.
